Before you start

You're rebuilding our Harbourside page from Week 7 with Bootstrap. The page you start with has no CSS at all. By the end it has a navbar that folds into a menu button on a phone, a banner, the menu as cards, a striped table, and Harbourside's own colours.

Work through Try Its 1 to 6 in order. Each one adds one part. Plan on about an hour.

  1. Run git pull, and open the Week 11 folder in VS Code.
  2. Open activity/index.html. Right-click it and pick Open with Live Server (or click Go Live).
  3. It should look plain: a big logo, a bullet-point menu, Times New Roman. That's right. That's where we start.
  4. You need the internet: Bootstrap loads from the web.

How each Try It works

The comments in index.html say where each Try It goes, like <!-- Try It 3: ... -->. Find the comment, use the Copy button on the code, paste it where it says, save, and look at the page. Then read What's new to see what each class did.

Stuck?

The finished page is in activity/answer/. Peek at it if you need to, but if you copy from it, change ../images/ to images/. The answer file is one folder deeper, so its image paths are different and your logo and photo will break.

The navbar

  1. In <header>, delete the logo <img> line, and the whole old <nav>, from <nav down to </nav>. Keep the <h1> for now. Try It 3 replaces it.
  2. Paste the navbar where the logo was, at the top of the header, above the <h1>.
  3. Scroll to the bottom. Paste the script just before </body>, where the Try It 2 comment is.
  4. Save. Make the window narrow (or press Ctrl + Shift + M in DevTools and pick a phone).

What's new

  • It's last class's pattern twice. The menu button has data-bs-toggle="collapse" and data-bs-target="#mainNav", which opens the div with id="mainNav". The Menu link has data-bs-toggle="dropdown".
  • navbar-expand-md: the full menu from md (768px) up, a menu button below that.
  • bg-harbour isn't Bootstrap. It's ours, our navy, already in style.css.
  • data-bs-theme="dark" tells Bootstrap the background is dark, so the links and the menu button turn light.
  • d-flex align-items-center gap-2 is Week 8's flexbox, as classes: the logo and the name side by side.
  • ms-auto pushes the links to the right (margin-start: auto).

Check it

Menu button does nothing?

  • The script is missing, or isn't just before </body>. Bootstrap gives no error. It just does nothing.
  • The id on the collapse div doesn't match data-bs-target exactly (#mainNav goes with id="mainNav").
  • No logo? Its path must be images/logo.svg, not ../images/logo.svg.

The menu as cards

  1. In <section id="menu">, keep the <h2>Our Menu</h2>.
  2. Replace all four <article>s under it (and the Try It 4 comment) with the block below.
  3. Save, and look at it at three widths: about 360px, 700px and 1100px.

What's new

  • <div class="row g-4"> wraps all the cards. Each card sits in a col-sm-6 col-lg-3 column.
  • Count the columns at each size, out of 12. Under 576px no class applies, so each card is full width. From sm (576px): 6 of 12, so 2 across. From lg (992px): 3 of 12, so 4 across.
  • card and card-body make the box. h-100 makes every card the full height of its column, so they line up. shadow-sm is a light shadow.
  • class="card-title h5" on the <h3>: the right heading level, at a smaller size.
  • Each article keeps its id, so the dropdown links in the navbar still jump to it.
  • badge text-bg-warning is the yellow Today's special label.

Check it

Check yourself

Your hours table is wider than a phone screen. What does table-responsive do about it?

  1. A Shrinks the text until the table fits
  2. B Stacks the columns on top of each other
  3. C Lets the table scroll sideways inside its own box
  4. D Hides the columns that don't fit
Show the answer

C. The table-responsive div gets overflow-x: auto, so only the table scrolls and the rest of the page stays still. We did this by hand in Week 7 with a table-wrap div. Try it: phone width in the device toolbar, then drag the table sideways.

Try It 6about 8 min

Make it look like Harbourside

  1. Open activity/style.css. It already has .bg-harbour.
  2. Paste the rules below under the Try It 6: make it yours heading.
  3. Save, and hover the See the menu button in the banner.
  4. Then make it yours: change a colour, a font, or a Bootstrap class. Anything you like.

What's new

  • Georgia headings and orange-red prices: ordinary CSS. It works because style.css is linked after Bootstrap.
  • .special ties with Bootstrap's .card (one class each), so ours wins because it's read last.
  • .btn-harbour doesn't set background-color. It sets Bootstrap's button variables, like Example 01, so the hover and click colours are ours too. If you set background-color instead, the hover goes back to Bootstrap's blue, because Bootstrap's .btn:hover is more specific.
  • The whole style.css is about 40 lines. Week 9's was about 300. That's what a framework buys you.

Check it

Bootstrap's rule still winning?

Right-click the element, choose Inspect, and look at the Styles panel. Bootstrap's rule may be more specific than yours, like .btn:hover. Crossed-out rules are the ones that lost.

Check yourself

Both rules are one class, so they tie on specificity. Which background does the special card get?

  1. A White: .card is Bootstrap's own class, so it wins
  2. B Cream: they tie on specificity, and ours is read last
  3. C White: Bootstrap's file is bigger and loads first
  4. D Neither: you need !important to beat a framework
Show the answer

B. Two steps, in order. 1. Is one selector more specific? Then it wins, whatever the order. 2. If they tie, the one the browser reads last wins. That's why style.css goes after Bootstrap's link. !important works too, but it's a last resort: it's how stylesheets become impossible to fix.
